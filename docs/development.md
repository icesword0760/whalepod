# 开发与发布边界

## 本次源码快照

本仓库初次发布取自实际打包使用的 DSH 0.1.5 插件工作树，而非早期 0.1.2 开发目录。保留内部插件名以维持兼容，未修改用户存储数据。

## DSH 补丁

`patches/BASE_COMMIT` 记录官方 DSH 基线。`dsh-0.1.5.patch` 包含该基线之后本地已提交和未提交的配套修改，以及新增源码和测试：多会话渲染、侧栏插槽、菜单高度、文件拖放、外部链接、系统代理、技能初始化、桌面分发等。

补丁不含依赖目录、个人配置或图标二进制；图标使用 README 中的复制步骤。升级 DSH 时应逐项核对补丁，避免重复应用已被上游接纳的修改。

这些是本地集成补丁，不代表上游已合并。测试通过与完整的首次安装验证分开记录。

## 桌面构建

桌面应用由 DSH 的 `apps/desktop` 构建，本仓库 `pnpm run build` 仅构建插件。

本地测试签名入口为 `DSH_DESKTOP_LOCAL_ADHOC=1`；它不是 Developer ID 签名或 Apple 公证。发布 App 还需把插件及其 bundle 声明纳入桌面 runtime inventory，验证空配置目录首次启动、插件启用、资源完整性和签名。仅复制插件构建文件到 App 不等于完成分发集成。

现有测试安装包在本机做过签名完整性、DMG 校验及空配置初始化检查；异机安装仍需验收。仓库首次上传不附带未经整理的本机打包脚本或个人配置。

## 贡献前检查

运行 `pnpm run check`。涉及布局、拖动、横向滚动、通知或窗口尺寸的修改还需在 Electron 实际窗口验证；浏览器测试不是桌面验收的替代。

提交问题时避免附 API 密钥、完整个人会话或未脱敏的连接器凭据。

## WhalePod 应用名称

本地分发构建的 productName、菜单、启动提示与窗口标题使用 WhalePod。Bundle ID、内部插件名、`~/.dsh` 和 Electron 用户数据目录保持原值，升级时保留原会话与设置。首次从独立布局插件升级到内置插件时，原插件会备份到 profile 内的 `.whalepod-plugin-backups/`，再连接内置版本。
